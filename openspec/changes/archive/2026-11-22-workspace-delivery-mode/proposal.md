# Proposal

## Why

SpecLearn currently only supports sandbox mode: students practice in an isolated branch or directory, never touching real production files. This means senior developers who want to learn a new technology or architectural pattern *while* building something real for their team have no supported path — the sandbox walls turn SDL into a pure training tool and rule out guided, production-quality feature delivery. Adding a `workspace` mode opens SDL to teams who want agents to mentor real feature work, not just practice exercises.

## What Changes

- **`COURSE-SPEC` schema**: add `mode?: "sandbox" | "workspace"` to the root (default `"sandbox"` for full backward compatibility). Add optional `target_files` array per module (workspace mode maps learning directly to real repo paths). Add optional `regression_command` per module's `verification` block (workspace mode can run a full regression suite before marking a module complete).
- **`/slx:propose` skill**: support `--workspace` flag; auto-detect workspace intent from an existing feature spec or ADR in the prompt. When delivery mode is not specified, explicitly ask during calibration whether the course should target an isolated `sandbox` or real repository files (`workspace` mode). Generate a `mode: workspace` COURSE-SPEC whose modules map to real `target_files` in the repository.
- **`/slx:start` skill**: announce the course's configured `mode` (`sandbox` or `workspace`) before scaffolding, support `--sandbox` / `--workspace` CLI overrides, and offer the learner a quick confirmation or option to switch modes for their session (especially useful for external or team-shared courses). Persist any session mode override in local state (`.speclearn/state/progress.json`) rather than mutating shared `COURSE-SPEC` files. Add workspace-mode Socratic mentor rules — guide edits *inside* `target_files` without writing the full implementation; keep the git diff clean and PR-ready at every step.
- **`/slx:explain` skill**: enforce that all temporary examples and scratchpad files go inside `.speclearn/scratchpad/` only — never inside production folders or `target_files`.
- **`/slx:verify` skill + `speclearn verify` CLI**: in workspace mode, run targeted feature tests with tamper-proof check and optionally execute `regression_command` before advancing the learning path.
- **`speclearn start` CLI**: support `--sandbox` and `--workspace` flags to select or override the session delivery mode without modifying the course file.
- **`speclearn init`**: add `.speclearn/state/` and `.speclearn/scratchpad/` to `.gitignore` (idempotent).
- **All agent adapters** (Claude Code, GitHub Copilot, Cursor, Antigravity, Generic/AGENTS.md): sync workspace-mode Socratic mentor rules, mode announcement, and session override handling so the agent sounds like a pragmatic senior teammate across all tools.
- **`README.md` and `/docs`**: document both modes in plain developer language with practical examples, including how to override delivery modes for external or team-shared courses.

## Capabilities

### New Capabilities

*(none — all changes extend existing capabilities)*

### Modified Capabilities

- `course-spec-format`: add `mode`, `target_files`, and `regression_command` fields to schema; new backward-compatibility and workspace validation scenarios
- `sdl-pedagogy-skills`: update propose calibration for delivery mode; update start skill for mode announcement, session override option, and in-place target-file guidance; update explain and verify skills
- `learning-progress-state`: record session delivery mode override in `.speclearn/state/progress.json` without modifying shared course specification files
- `agent-adapter-system`: add workspace-mode Socratic mentor rules and mode announcements across all five adapters; add scratchpad enforcement rule
- `deterministic-module-verification`: add `regression_command` execution scenario — run regression suite after feature tests pass, block completion on failure
- `cli-entrypoint`: update `speclearn start` with `--sandbox` and `--workspace` flags; update `speclearn verify` to execute declared `regression_command` after feature tests pass
- `learning-sandbox-isolation`: clarify that sandbox isolation applies only when effective session mode is `sandbox`; workspace mode operates directly in real project files

## Impact

- **Schema**: `src/schema/course-spec.ts` — Zod additions to `courseSpecSchema`, `courseModuleSchema`, and `moduleVerificationSchema`
- **Generated JSON Schema**: `schemas/course-spec.v1.schema.json` and `.speclearn/course-spec.v1.schema.json` regenerated by `pnpm build`
- **Adapter templates**: `src/adapters/templates.ts` — workspace-mode rules added to `start`, `explain`, and `verify` command templates
- **Adapter builtins**: `src/adapters/builtins.ts` — description strings updated with workspace context
- **CLI verify command**: `src/commands/verify.ts` (or inline in `src/cli.ts`) — run `regression_command` subprocess when declared
- **CLI init command**: init logic in `src/cli.ts` or `src/commands/init.ts` — idempotent `.gitignore` append
- **Examples**: `examples/typescript-clean-architecture.course.md`, `examples/python-async-resilience.course.yaml` — remain valid; no breaking changes
- **Docs**: `README.md`, `docs/` — new workspace mode section with practical examples
- **Tests**: `tests/schema.test.ts`, `tests/adapters.test.ts`, `tests/verify.test.ts`, `tests/examples.test.ts` — updated or added assertions for new fields and behaviors
